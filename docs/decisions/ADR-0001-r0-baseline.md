# ADR-0001: R0 기준선 구현

- Status: `PROPOSED`
- Date: `2026-08-28`
- Owners: `A-00`, `A-02`, `A-50`

## Context

게임별 제작 계획에 앞서 에이전트의 권한, 책임, 입력·출력 계약과 검증 방법을
먼저 고정해야 한다. 공급자가 바뀌더라도 동일한 작업·인계·산출물 계약을 유지해야
하며, 에이전트가 무승인으로 지식·코드·운영 환경을 변경해서는 안 된다.

## Decision

1. Constitution을 최상위 저장소 정책으로 둔다.
2. 상시 에이전트는 9종으로 고정하고 세부 작업자는 필요 시 생성한다.
3. Task, Handoff, Artifact를 공급자 중립 JSON Schema로 정의한다.
4. Registry와 예제의 참조 무결성을 자동 검증한다.
5. 현재 저장소 상태를 `R0 candidate`로 두며 사용자 승인 전 `R0 approved`로 바꾸지 않는다.
6. `R5` 전에는 상용 제작 일정을 산정하지 않는다.

## Consequences

- 초기 구축 속도보다 변경 추적과 품질 측정이 우선된다.
- 외부 AI 공급자 교체가 계약 소비자에게 직접 전파되지 않는다.
- SYS-004 이후 구현은 본 기준선에 종속된다.
- 기준선 변경은 ADR과 버전 변경을 필요로 한다.
