# R2 후속 유닛 후보

- 작성일: `2026-09-01`
- 작성 근거 작업: `R2-RNG-0001`
- 상태: `CANDIDATE / NOT_READY`
- 대상: `docs/approvals/R1-evidence-closure.md` 3절이 `OPEN`으로 남긴 이월 위험 2건

## 0. 이 문서의 지위

이 문서는 **Task Contract가 아니다.** 여기 적힌 어떤 항목도 착수 허가가 아니며, `tasks/`에
계약이 발행되기 전에는 구현을 시작할 수 없다. `R2-RNG-0001`은 정확히 그 순서를 어겨
게이트 위반을 남겼고, 그 기록은 `docs/operations/R2-RNG-0001-recovery.md`에 있다. 이 문서는
그 실패를 반복하지 않기 위해 **범위를 계약보다 먼저, 그러나 계약과 분리해서** 적어 둔 것이다.

각 후보를 실제 작업으로 바꾸려면 다음이 선행되어야 한다.

1. `contracts/task.schema.json`에 유효한 `tasks/<unit_id>.json`을 `READY`로 발행한다.
2. 같은 `unit_id`의 Artifact Contract와 Handoff Packet을 함께 만든다.
   `scripts/validate_baseline.py::validate_collaboration`이 셋을 함께 요구한다.
3. `HIGH` 위험 유닛은 `A-50`, `A-02`, `A-00`을 승인자로 포함해야 한다.
4. 사용자 승인은 착수 권한이며 최종 QA 게이트 판정이 아니다.

## 1. 일정에 관한 고정 제약

`AGENTS.md` Non-negotiable rules와 `agents/registry.yaml`의
`production_schedule_policy: prohibited_before_r5`에 따라, 이 문서는 후보들의 **착수일,
완료일, 기간, 순번 마감, 출시일을 정하지 않는다.** 아래의 "선행 관계"는 기술적 의존성이지
일정이 아니다. 상용 제작 일정과 출시일은 `R5` 승인 이후에만 확정한다.

예산 수치 역시 적지 않는다. 예산은 Task Contract의 `budget`에서 승인 주체가 정한다.

## 2. 이월 위험 A — 데이터베이스 격리 수준과 동시성·장애 복구

### 유닛 R2-DBC-0002 — `CLOSED_PENDING_REVIEW` (계약 발행됨)

이 항목은 더 이상 후보가 아니다. `tasks/R2-DBC-0002.json`이 발행되었고 그 계약 아래에서
구현과 자동 검증이 끝났다. 남은 것은 인간 게이트뿐이다.

| 항목 | 내용 |
| --- | --- |
| 소유자 | `A-02` Platform Integrator |
| 위험 등급 | `HIGH` (원장·정산·감사 경로에 닿는다) |
| 필수 승인자 | `A-50`, `A-02`, `A-00`, `USER` — 전건 `PENDING` |
| 산출물 | `studio_core/durable_state.py`, `games/roulette/durable-state-contract.yaml`, `games/roulette/durable-state-schema.sql`, `tests/test_durable_state.py`, `docs/games/R2-durable-state.md` |
| 증거 | `docs/approvals/R2-DBC-0002-validation-report.md`, `handoffs/R2-DBC-0002-handoff.json`, `audit/events/R2-DBC-0002-events.json` |
| 선행 관계 | `R2-RNG-0001`의 추첨 기록·감사 이벤트 형태가 저장 대상이므로 기술적으로 뒤에 온다 |

아래 "닫아야 할 공백"과 "수용 기준 뼈대"는 계약 발행 전에 적은 원문이며, 무엇을 근거로
범위를 잡았는지 남기기 위해 그대로 둔다. 실제 충족 여부는 위 증거 문서에서 판정한다.

**닫아야 할 구체적 공백** (계약 발행 시점 기준, 모두 당시 코드에서 실측 가능한 사실이었다)

- `studio_core/rng.py`의 엔진 상태는 프로세스 메모리에만 있다. 락은 한 프로세스 안의 경쟁만
  막고, 재시작하면 모든 `request_id`를 잊는다. 같은 라운드에 두 번째 권위 결과가 생길 수 있고,
  이는 `handoffs/R2-RNG-0001-handoff.json`에 `MEDIUM` 위험으로 이미 기록되어 있다.
- `AuditChain`은 인메모리 해시 체인 참조 구현이다. 내구 저장소가 없으므로 감사 불변성
  (`policies/audit.yaml`의 `integrity.immutable`)은 아직 선언이지 보장이 아니다.
- `audit_event_ref` 순번이 엔진 인스턴스마다 1에서 다시 시작한다. 전역 유일성이 없다.
- `studio_core/ledger.py`의 멱등성은 호출자가 넘긴 `idempotency_key` 집합에 의존한다.
  동시 요청 두 건이 같은 키를 동시에 제출하는 경로는 저장소 격리 수준의 문제이며
  현재 코드 밖이다.

**제안 수용 기준 뼈대**

- 추첨·정산·감사 쓰기가 하나의 원자 단위로 커밋되거나 전부 롤백된다.
- 프로세스 재시작 뒤에도 같은 `request_id`가 원본 결과를 반환한다.
- 동시 중복 요청이 정확히 하나의 권위 결과만 만든다. 경쟁 조건은 단위 시험이 아니라
  실제 동시 실행으로 증명한다.
- 감사 이벤트가 전역 유일 참조를 갖고, 체인 검증이 저장소 재적재 뒤에도 통과한다.
- 격리 수준과 그 선택 근거가 문서로 남고, 더 낮은 수준에서 깨지는 시나리오가 시험으로 존재한다.

**명시적 범위 밖**: 부하 시험, 침투 시험, 실제 운영 배포. 이 세 항목은 아래 3절의
`R2-NET-0003`, `R2-LOAD-0004`, `R2-SEC-0005`로 이월되었고 셋 다 `OPEN`이다.

## 3. 이월 위험 B — 실제 네트워크 재접속, 부하, 보안 침투 시험

세 항목은 성격이 다르므로 하나의 유닛으로 묶지 않는다. 검증 방법과 필요한 권한이 다르고,
한 유닛으로 묶으면 어느 하나의 실패가 나머지의 증거까지 무효로 만든다.

### 후보 유닛 R2-NET-0003 (제안 식별자) — 재접속과 라운드 연속성

| 항목 | 내용 |
| --- | --- |
| 제안 소유자 | `A-30` Client / `A-02` Platform 공동 검토 |
| 위험 등급 제안 | `HIGH` (라운드 상태와 정산 결과에 닿는다) |
| 선행 관계 | 내구 상태가 필요하므로 `R2-DBC-0002` 뒤 |

- 끊긴 클라이언트가 재접속했을 때 서버 권위 라운드 상태만을 근거로 복구되는지 확인한다.
  `games/roulette/round-state.yaml`의 `guards.client_authority: denied`가 실제 재접속
  경로에서도 유지되어야 한다.
- 재접속이 베팅 마감(`LOCKED`) 이후의 베팅을 되살리지 못해야 한다.
- 정산 통지 유실 후 재접속에서 이중 지급이 발생하지 않아야 한다.
- **범위 밖**: 처리량 목표치, 침투 시험.

### 후보 유닛 R2-LOAD-0004 (제안 식별자) — 부하와 성능 특성

| 항목 | 내용 |
| --- | --- |
| 제안 소유자 | `A-02` Platform Integrator |
| 위험 등급 제안 | `MEDIUM` (정확성이 아니라 용량 특성) |
| 선행 관계 | `R2-DBC-0002`, `R2-NET-0003` 뒤 |

- 동시 라운드·동시 플레이어 부하에서 정산 정확성과 감사 완전성이 유지되는지 측정한다.
- 부하 하에서 추첨 직렬화 락이 만드는 대기 특성을 측정하고 기록한다.
- 측정은 **관측**이지 목표가 아니다. 용량 목표치(SLO)는 이 유닛에서 확정하지 않는다.
  목표치는 제작 규모 결정에 종속되고, 그 결정은 `R5` 이전에 하지 않는다.
- **범위 밖**: 일정, 출시 용량 약속, 인프라 조달.

### 후보 유닛 R2-SEC-0005 (제안 식별자) — 보안 침투 시험

| 항목 | 내용 |
| --- | --- |
| 제안 소유자 | `A-02` Platform Integrator, 독립 검증 `A-50` |
| 위험 등급 제안 | `HIGH` |
| 선행 관계 | 앞의 세 유닛이 만든 표면을 대상으로 하므로 마지막 |

- 대상 표면과 허가 범위를 **먼저 문서로 확정하고 사용자 승인을 받은 뒤에만** 수행한다.
  `policies/security.yaml`은 기본 거부이며, 시험 자체가 승인 없이 시작될 수 없다.
- 클라이언트 권위 위조, 베팅 마감 우회, 정산 재요청, 감사 이벤트 위조·삭제, 시드 참조
  역추적을 대상으로 한다.
- 비밀값은 저장소·프롬프트·로그에 남지 않는다. 발견 사항도 같은 규칙을 따른다.
- **범위 밖**: 운영 환경 대상 시험, 외부 대상 시험, 탐지 회피.

## 4. 이 문서가 만들지 않는 것

- Task Contract, 착수 허가, 예산 배정
- 일정, 기간, 마감, 출시일
- `A-50` 또는 사용자의 최종 QA 게이트 판정
- 위 후보 식별자에 대한 선점. 실제 계약 발행 시 식별자는 재확인한다.
