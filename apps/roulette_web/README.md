# 유러피언 싱글제로 룰렛 · 내부 로컬 플레이어블 슬라이스 (`R4-UI-0006`)

**내부 프로토타입입니다. 가상 칩만 사용하며 현금 가치가 없습니다.**
**Internal prototype. Virtual chips only. No cash value.**

칩을 사거나 충전하거나 밖으로 내보내는 경로는 존재하지 않습니다. 로그인, 계정 등록, 개인정보
수집, 결제, 환전, 실물 보상, 외부 네트워크 호출, 텔레메트리 전송이 모두 없습니다.

## 실행

저장소 루트에서 다음 한 줄이 전부입니다. 빌드 단계, Node.js, npm, 외부 패키지, CDN 자산이
필요하지 않습니다. 파이썬 3.11 이상과 `PyYAML`(저장소 기준선이 이미 요구하는 의존성)만 있으면
됩니다.

```bash
python -m apps.roulette_web.server
```

그다음 브라우저에서 <http://127.0.0.1:8765/> 를 엽니다.

선택 인자:

| 인자 | 기본값 | 설명 |
| --- | --- | --- |
| `--host` | `127.0.0.1` | 바인딩할 루프백 호스트. 루프백이 아닌 값은 기동 시점에 거부됩니다. |
| `--port` | `8765` | TCP 포트. `0`을 주면 운영체제가 빈 포트를 고릅니다. |
| `--db` | 없음 | 런타임 SQLite 경로. 지정하지 않으면 저장소 밖 기본 경로를 씁니다. |
| `--verbose` | 꺼짐 | 요청 한 건마다 한 줄씩 표준 오류로 기록합니다. 기본은 무기록입니다. |

예:

```bash
python -m apps.roulette_web.server --port 9000 --verbose
```

## 중지

서버를 띄운 터미널에서 `Ctrl+C`를 누릅니다. 프로세스는 `KeyboardInterrupt`를 받고
`stopped`를 출력한 뒤 소켓과 데이터베이스 연결을 닫고 종료합니다. 별도의 정지 명령이나 정지용
엔드포인트는 없습니다.

터미널을 이미 닫아 버렸다면 포트를 잡고 있는 프로세스를 확인해서 종료합니다.

```bash
# Windows PowerShell
Get-NetTCPConnection -LocalPort 8765 -State Listen | Select-Object OwningProcess
Stop-Process -Id <PID>

# macOS / Linux
lsof -nP -iTCP:8765 -sTCP:LISTEN
kill <PID>
```

`kill -9`나 강제 종료는 마지막 수단으로만 씁니다. 정상 종료가 아니어도 커밋된 라운드는
데이터베이스에 남지만, 진행 중이던 열린 라운드의 담아 둔 베팅은 사라집니다(아래 한계 참고).

## 루프백 전용

이 서버는 루프백 주소에만 바인딩합니다. `127.0.0.1`, `::1`, `localhost`, `ip6-localhost` 외의
호스트는 바인딩을 시도하지 않고 기동 시점에 거부되며, 이름이 루프백이 아닌 주소로 풀리는 경우도
거부됩니다. 기본값은 `''`(모든 인터페이스)가 아니라 `127.0.0.1`입니다.

**같은 기계 안에서는 이 서버가 보호되지 않습니다.** 인증, 세션, 접근 제어가 전혀 없으므로 이
기계에서 실행 중인 모든 프로세스와 모든 사용자 계정이 API에 접근할 수 있습니다. 공유 기계나
신뢰할 수 없는 로컬 소프트웨어가 있는 환경에서는 실행하지 마십시오. 원격 노출, 리버스 프록시
경유 공개, 포트 포워딩은 이 유닛의 범위 밖이며 그렇게 쓰도록 만들어지지 않았습니다.

## 조작

모든 조작은 마우스·터치와 키보드 양쪽으로 가능합니다. 조작 요소는 전부 실제 `button`과
`input`이며, `Tab`/`Shift+Tab`으로 이동하고 `Enter`/`Space`로 실행합니다. 라디오 그룹(칩 금액,
베팅 종류)은 방향키로 고릅니다. 첫 번째 `Tab`에서 나타나는 건너뛰기 링크로 베팅 보드까지 바로
이동할 수 있습니다.

| 조작 | 하는 일 |
| --- | --- |
| 칩 금액 (1 / 5 / 25 / 100 / 500) | 다음에 담을 베팅의 가상 칩 금액을 고릅니다. |
| 베팅 종류 (스트레이트 / 스플릿 / 스트리트 / 코너 / 식스라인) | 인사이드 베팅에 필요한 번호 개수를 정합니다. |
| 보드의 번호 칸 | 번호를 고릅니다. 필요한 개수가 차면 베팅 슬립의 대기 목록에 담깁니다. |
| 아웃사이드 칸 (더즌, 컬럼, 1–18, 짝수, 빨강, 검정, 홀수, 19–36) | 해당 아웃사이드 베팅을 바로 대기 목록에 담습니다. |
| 지우기 | 아직 제출하지 않은 대기 베팅을 모두 비웁니다. 서버가 확정한 베팅에는 영향이 없습니다. |
| 리베팅 | 직전 라운드와 같은 베팅을 대기 목록에 다시 담습니다. |
| 스핀 | 대기 베팅을 서버에 제출하고 추첨을 요청합니다. 결과·지급액·잔액은 서버가 정합니다. |
| 새 라운드 | 정산이 끝난 뒤 새 라운드를 엽니다. 진행 중에는 거부됩니다. |
| 다시 시도 | 실패한 직전 요청을 **같은 요청 식별자로** 재시도합니다. 중복 청구가 생기지 않습니다. |

화면 낭독기 사용자를 위해 라운드 상태, 결과, 잔액 변화가 `aria-live` 영역으로 안내되고,
오류는 `role="alert"`로 즉시 안내됩니다. `prefers-reduced-motion`을 켠 환경에서는 휠 회전
연출이 비활성화되고 결과만 즉시 표시됩니다.

## API 요약

모든 응답은 JSON이며 위의 공개 문구(`notice`)를 함께 싣습니다. 모든 응답에는 아래 보안 헤더가
붙습니다: `Content-Security-Policy`, `X-Content-Type-Options`, `X-Frame-Options`,
`Referrer-Policy`, `Cross-Origin-Resource-Policy`, `Permissions-Policy`, `Cache-Control`.

| 경로 | 메서드 | 본문 | 하는 일 |
| --- | --- | --- | --- |
| `/api/state` | `GET` | 없음 | 권위 있는 테이블 상태 전체(잔액, 라운드, 보드, 한도, 최근 결과)를 반환합니다. |
| `/api/bets` | `POST` | `{"request_id": "...", "bet": {"type": "...", "selections": [...], "stake_units": 25}}` | 베팅 하나를 검증하고 열린 라운드에 기록합니다. 커밋은 없습니다. |
| `/api/spin` | `POST` | `{"request_id": "..."}` | 라운드를 잠그고 추첨·정산·감사 기록을 한 트랜잭션으로 커밋합니다. |
| `/api/new-round` | `POST` | `{"request_id": "..."}` | 종결된 라운드 뒤에 새 라운드를 엽니다. |

그 밖의 경로는 정적 자산으로만 처리되며 허용된 확장자(`.html`, `.css`, `.js`, `.svg`,
`.json`, `.webmanifest`)만 고정된 Content-Type으로 배급됩니다. 선언되지 않은 메서드, 알 수 없는
경로, 경로 탐색 시도는 모두 거부됩니다.

규칙:

- `request_id`는 멱등성 키입니다. 같은 식별자로 다시 보내면 엔트로피를 다시 쓰지 않고 원본
  결과를 그대로 돌려줍니다. 같은 식별자를 다른 내용으로 재사용하면 `REQUEST_ID_CONFLICT`로
  실패로 닫힙니다.
- 결과, 지급액, 잔액을 담은 요청은 무시되지 않고 `CLIENT_AUTHORITY_DENIED`로 거부됩니다.
- 통화 값은 전부 정수 최소 단위입니다. 요청 본문에 소수점 숫자가 있으면 파서 단계에서
  거부됩니다.
- 본문은 `Content-Length`가 필요하고 8 KiB를 넘을 수 없습니다. 청크 전송은 거부됩니다.
- 오류 본문은 `{"error": {"code": ..., "message": ...}, "notice": {...}}` 한 가지 모양이며
  스택 추적, 파일 경로, 데이터베이스 메시지를 담지 않습니다.

전체 선언은 `games/roulette/playable-slice-contract.yaml`에 있고, 기준선 검증기가 그 파일과
구현 상수를 대조합니다.

## 런타임 데이터베이스

권위 있는 상태는 SQLite 파일 하나에 들어 있고 **저장소 바깥**에 만들어집니다. 기본 경로는
플랫폼 임시 디렉터리 아래 `ts-studio-roulette-web/roulette-web.sqlite3`입니다.

- 다른 경로를 쓰려면 `--db <경로>` 또는 환경 변수 `ROULETTE_WEB_DB`를 지정합니다.
- 처음부터 다시 시작하려면 서버를 멈춘 뒤 그 파일과 `-wal`, `-shm` 사이드카를 지우면 됩니다.
- 이 파일은 저장소 내용이 아닙니다. `.gitignore`가 `*.sqlite3`, `*.sqlite`, `*.db`와 WAL/SHM
  사이드카를 제외하므로, 실수로 작업 트리 안을 가리켜 실행하더라도 커밋되지 않습니다.
- 재시작하면 커밋된 잔액, 정산, 최근 결과 목록이 그대로 복원됩니다. 여는 칩은 최초 1회만
  지급되며 재시작이 잔액을 초기화하지 않습니다.

## 알려진 한계

- **열린 라운드의 베팅은 내구적이지 않습니다.** 스핀 전에 서버를 멈추면 담아 둔 베팅은
  사라지고 재시작 시 새 라운드가 열립니다. 커밋된 것이 없으므로 칩은 잃지 않습니다.
- **단일 사용자, 단일 프로세스, 단일 테이블** 가정입니다. 다중 사용자 동시 테이블과 세션
  분리는 구현되어 있지 않습니다.
- **네트워크 재접속 보증이 없습니다.** 응답이 유실된 요청은 같은 `request_id`로 재시도해야
  안전하며, 자동 재접속·재동기화 계층은 없습니다(`R2-NET-0003`로 이월).
- **부하·성능 특성이 측정되지 않았습니다**(`R2-LOAD-0004`로 이월).
- **침투 시험을 수행하지 않았습니다**(`R2-SEC-0005`로 이월). 위의 보안 조치는 설계이자 자동
  시험의 대상이며, 침투 시험의 결과가 아닙니다.
- **브라우저 시각 QA가 수행되지 않았습니다.** 접근성과 반응형은 마크업·스타일시트 정적 검증과
  서버 응답 시험으로만 확인했습니다. 실기기 브라우저와 화면 낭독기를 쓴 사람 검사는 별도로
  필요합니다.
- **인간 최종 승인 전입니다.** 이 슬라이스는 내부 프로토타입이며 운영 배포 후보가 아닙니다.
  상용 클라이언트로 그대로 승격해서는 안 됩니다.
- 감사 이벤트와 정산은 `studio_core`의 승인된 경계를 그대로 사용하며, 이 패키지는 규칙·RNG·
  원장·내구 상태를 다시 구현하지 않습니다.
